# PHOENIX — Domain Context Reference

## LotusBook Scraping

### Page Structure
- URL: `https://lotusbook.site/cricket`
- **"In Play" section** at top → live matches
- **"Upcoming Events" section** below → scheduled matches
- 1X2 odds grid per match: Column 1 (Home), X (Draw), 2 (Away)
- Each column: Back price | Lay price
- Competition badges (ICC T20 World Cup, WPL, etc.)

### DOM Extraction (worker.py)
JavaScript runs inside Playwright to extract matches. Key logic:
- Walk up DOM from each match link to find section header
- If header contains "Upcoming" → `is_live = false`
- If time text matches date pattern (DD/MM/YYYY, "Tomorrow", "Today") → `is_live = false`
- Only trust live indicators when NOT in upcoming section
- Score patterns like "45/2" confirm live status

### Match ID Format
Generated by parser as `lb_` + hash of home+away+competition. Deterministic — same teams in same competition always produce same ID.

### Odds Validation
- Odds must be > 1.0 (decimal format)
- Back ≤ Lay (no reverse spread)
- Back-Lay spread < 50% of back price (reject extreme spreads)
- Null odds are allowed (partial data) but filtered to None by parser

## RL System

### Observation Space (48 features, float32)
| Group | Count | Source |
|---|---|---|
| Core Odds | 7 | Back/lay prices, margin, spreads |
| Momentum | 6 | Velocity, volatility, trend |
| Market Quality | 5 | Spread dynamics, efficiency, staleness |
| Match State | 7 | is_live, overs, wickets, score, run rates |
| Portfolio | 5 | Bankroll, exposure, positions, win rate |
| Position | 4 | Net exposure, hedge potential |
| Volume | 4 | Liquidity depth, imbalance |
| Bookmaker | 4 | Pricing patterns |
| Format | 4 | T20i/ODI/Test/Franchise one-hot |
| Timing | 2 | Match elapsed %, tick freshness |

**Data-only rule:** No cricket heuristics (no "death over penalty", no "team strength", no "venue factor"). Agent discovers all patterns from data.

### Action Space (9 discrete)
```
0 = HOLD (target: ~90% of actions)
1 = BACK_HOME_SM (1% bankroll)    5 = LAY_HOME_SM (1%)
2 = BACK_HOME_LG (3% bankroll)    6 = LAY_AWAY_SM (1%)
3 = BACK_AWAY_SM (1% bankroll)    7 = LAY_HOME_LG (3%)
4 = BACK_AWAY_LG (3% bankroll)    8 = LAY_AWAY_LG (3%)
```

### Reward Function (6 components)
1. **Bet Outcome** (dominant): P&L / bankroll * 10
2. **Patience**: +0.001 for HOLD when odds stable
3. **Overtrading Penalty**: -0.01 per bet over 15/hour
4. **Risk Breach**: -0.1 per % over 50% exposure
5. **Drawdown Penalty**: quadratic above 10%
6. **Sharpe Bonus**: end-of-episode, proportional to Sharpe ratio

### Curriculum Stages
1. **Pattern Recognition**: HOLD + BACK_HOME only, historical data
2. **Full Actions**: All 9 actions, historical data
3. **Live Simulation**: Live odds, virtual execution with slippage
4. **Adversarial**: Noise injection for robustness

### Graduation Criteria (all must hold for 14 consecutive days)
- Win rate > 55%
- ROI > 8%
- Sharpe ratio > 1.5
- Max drawdown < 15%
- 10+ profitable days in last 14
- 100+ bets in last 30 days

## Betting Math

### BACK Bet
- **Win**: profit = stake × (odds - 1)
- **Loss**: profit = -stake

### LAY Bet (you act as the bookmaker)
- **Win** (selection loses): profit = +stake
- **Loss** (selection wins): profit = -stake × (odds - 1)

### CLV (Closing Line Value)
Measures edge vs market: `CLV = (closing_odds / entry_odds) - 1`
Positive CLV = you got better odds than the market settled at.

### Implied Probability
`implied_prob = 1 / decimal_odds`
Overround = sum of all implied probs - 1 (bookmaker margin, typically 2-8%)

## UI Design Principles

### State Representation Rules
- **Dashboard** must show current lifecycle state prominently (from Redis, not hardcoded)
- **Match cards** show real-time status: is_live flag drives LIVE badge and scraping status
- **Empty states** always explain what needs to happen next (never blank)
- **Health indicators** must reflect actual service health (API, Redis, DB, Scraper)

### RL Debugging Quick Reference
| Symptom | Likely Cause | Fix |
|---|---|---|
| Agent always HOLDs | Entropy too low | Increase ent_coef to 0.05 |
| Agent over-trades | Weak penalty | Increase overtrading penalty coefficient |
| High win rate, negative ROI | Winning small, losing big | Check stake sizing |
| NaN in observations | Missing data not handled | Check pipeline for NaN → 0.0 replacement |
| Training diverges | Learning rate too high | Reduce to 1e-4 |
